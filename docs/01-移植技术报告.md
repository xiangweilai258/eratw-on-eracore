# eraTW 移植技术报告

本文记录把 eraTW（画蛇添足版）移植到 EraCore 的完整过程与技术细节。

> 补丁文件：`port/eratw-EE56-compat.patch`  
> 生成脚本：`port/make-patch.py`（可复现）

---

## 一、问题背景

### 1.1 两处兼容缺口

eraTW「画蛇添足版」使用了该支系魔改出的 **EEv56 扩展指令集**，而 `era-core` 的 `main` 分支  
只实现了基础 Emuera 指令。缺口分两类：

1. **EEv56 兼容层** —— eraTW 大量调用的扩展指令（SQL 函数族、寻路、文本背景色、HTML 输出等）
2. **插件加载链路** —— eraTW 自带一个 Emuera.EM 插件，加载时会抛异常拖垮整个初始化

### 1.2 补丁来源

这些实现原本存在于 `era-core` 的 `mcp` 分支（该分支能跑 eraTW，但无法编出非 Windows 产物）。  
本补丁的工作就是把 `mcp` 分支的实现**平移到** `main` 分支。

### 2.1 平移策略：新建分部文件，零改动冲突

探查 `main` 分支后发现两个有利事实：

1. **命名空间没变** —— main 把文件挪到了 `EraCore.Core/Shared/`，但内部命名空间仍是  
   `MinorShift.Emuera.*`。所以是**平移**（复制 + 微调），不是重写。
2. **main 把 `Creator.Method.cs` 拆成了多个分部文件**，原文件只剩一个壳：
   ```csharp
   namespace MinorShift.Emuera.GameData.Function;
   internal static partial class FunctionMethodCreator { }
   ```

→ 因此采用最干净的方案：**新建 `Creator.Method.EE56.cs` 装全部实现，现有文件零改动**，  
只在 6 个登记点各插一行。

## 四、插件加载修复

### 4.1 问题

`PluginManager.LoadPlugins()` 加载 eraTW 自带的 `plugins/ClassLibrary1.dll` 时抛  
`ReflectionTypeLoadException`：

```
Could not load file or assembly 'Emuera, Version=1.824.0.0'
  at System.Reflection.RuntimeModule.GetTypes()
  at PluginManager.LoadPlugins()  ...PluginManager.cs:line 297
[csm] Process.Initialize returned false          ← 引擎初始化被整个拖垮
```

**成因**：`ClassLibrary1.dll` 编译时引用的是程序集名 **`Emuera`**（Emuera.EM 的工程名），  
而本引擎的 `<AssemblyName>` 是 **`EraCore.Core`**。

### 4.2 可行性核对（决定「修复」而非「跳过」）

| 核对项              | 结果                                                                             |
| ---------------- | ------------------------------------------------------------------------------ |
| 插件引用的类型          | `MinorShift.Emuera.Runtime.Utils.PluginSystem.PluginManifestAbstract`          |
| main 分支同名类型的命名空间 | **完全一致** ✓                                                                     |
| 插件性质             | Emuera.EM 插件                                                                   |
| 插件内容             | `PluginManifest` + `CalculateMethod` / `DifferentateMethod` / `IntegralMethod` |
| 实际差异             | **只有程序集标识不同**                                                                  |

→ 类型全名一致，做一次程序集重定向即可让它真正加载并工作。

### 4.3 三处修复

**① 程序集标识重定向**（核心）

```csharp
private static readonly string[] LegacyEmueraAssemblyNames = ["Emuera", "Emuera.EM", "EraCore"];

private static Assembly? ResolveLegacyEmueraAssembly(object? sender, ResolveEventArgs args)
{
    var requested = new AssemblyName(args.Name).Name;
    // 匹配旧名 → 返回 typeof(PluginManager).Assembly（即 EraCore.Core）
}
```

在 `LoadPlugins()` 开头注册一次 `AppDomain.CurrentDomain.AssemblyResolve`。

**② `GetTypes()` 容错**（防止未来任何不兼容插件再次拖垮引擎）

```csharp
try { dllTypes = DLL.GetTypes(); }
catch (ReflectionTypeLoadException ex)
{
    // 取回已成功加载的部分（ex.Types 失败项为 null），失败原因降级为警告
    dllTypes = ex.Types.Where(t => t != null).Select(t => t!).ToArray();
    EmueraLog.Warn("plugins", "...有 N 个类型无法加载，已跳过：...");
}
```

同时把 `Assembly.LoadFrom` / `Activator.CreateInstance` 也纳入 try/catch，  
并把原来两处 `//TODO: throw warning` 换成真实的分级日志。

**③ 插件目录名大小写容错**（★ 面向 Linux / Android / 鸿蒙的前置修复）

```csharp
// Windows 惯用 "Plugins"，但 eraTW 等游戏用小写 "plugins"。
// 在大小写敏感文件系统上，写死大小写会静默跳过插件。
private static string? ResolvePluginDir(string exeDir) { /* 大小写不敏感匹配 */ }
```

> 开发机的文件系统默认大小写不敏感（`plugins` 与 `Plugins` 指向同一 inode），  
> 这个 bug 被掩盖了；**到 Android / 鸿蒙上才会暴露**。提前修掉。

### 4.4 游戏侧：`pluginsAware.txt`

Emuera 有一道安全闸门：游戏带插件时，必须在游戏根目录放 `pluginsAware.txt` 才允许加载，  
否则抛 `ExeEE`。eraTW 发行包没有这个文件 → 即使修好程序集绑定，仍会撞上这道闸门。  
按其报错原文指示创建该文件（内含知情声明与插件清单）。

### 4.5 实测结果

```
[plugins] 旧程序集引用 "Emuera" → 重定向到 EraCore.Core
[plugins] 已加载插件 Math Expansion Plugin v1.0（3 个方法）

ReflectionTypeLoadException 出现次数: 0        （修复前：致命）
[ErbLoader] LoadErbDir done: noError=True, labels=112724
[csm] Process.Initialize OK
→ 10 秒到达标题画面（插件 + qol 数据库全在）
```

### 4.6 一个诚实的补充

搜过 eraTW 全部 3931 个 ERB：`CALCULATE(` / `DIFFERENTIATE(` / `INTEGRAL(` **零命中** ——  
所以这个插件 eraTW 自己并不调用，是发行包附带的通用件。

**但修复依然必需**：只要 `ClassLibrary1.dll` 在场，`GetTypes()` 就会抛异常把初始化整个拖垮。  
修复的价值在于 ① eraTW 能跑起来；② 对其他真正用插件的 era 游戏，功能完整可用。

## 六、接口速查（踩坑换来的）

| 项                               | 值                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------ |
| CLI 产物路径                        | `EraCore.Cli/bin-aot/Release/net10.0/`（**不是 `bin/`**）                          |
| 启动                              | `EraCore.Cli --server --port 8099`                                             |
| **`--exedir` 在 server 模式不自动加载** | 必须 `POST /load-game {"gameDir":"..."}`                                         |
| 输入                              | `POST /input {"value":"<字符串>"}`；传数字报 `Invalid JSON`                            |
| 加载完成判据                          | `GET /state` → `state == "WaitInput"`                                          |
| `inputType`                     | 会变（`IntValue` / `EnterKey`），`needValue` 相应变化                                   |
| 屏幕                              | `GET /snapshot` → `{lines, bgColor, state, inputType, needValue, ...}`         |
| 其他端点                            | `/session` `/control/*` `/config` `/game/scan` `/game/dirs` `/assets/**` `/ws` |

### 6.1 `/snapshot` 的坑

`lines` 元素是**多层嵌套**结构 —— `{entries:[{segments:[{text:"..."}]}]}`。  
必须递归收集，直接取 `e["segments"]` 会全部拿到空字符串。  
（`tools/snapshot-dump.py` 已处理）

### 7.1 Debug 打包的一个坑

Debug 构建在支持 fast-deploy 的设备上默认 `EmbedAssembliesIntoApk=false` →  
清单写 `extractNativeLibs="true"` → `.so` 被 DEFLATE 压缩 → **启动即 `libmonodroid abort_application`**。

修复：`EmbedAssembliesIntoApk=true` + 清单钉 `extractNativeLibs="false"`。  
（`tools/build-android.sh` 已内置）

## 九、已知未实现

### NF 指令族

画蛇添足版解释器 v9 的 **NF 后缀输入指令族**（`TINPUTNF` / `TINPUTSNF` / `TONEINPUTNF` / `TONEINPUTSNF`），  
eraTW 的**动态地图动画**依赖它。未实现时的表现是：地图可用，但**不播放动画**。

**绕过方式**：把地图类型设为「[2] 颜色地图」或「[3] 经典」即可（仅无动画，功能正常）。
