## v0.5.3 · 2026-10-10

> ★ 本版解决的是**「看起来对不对」** —— 界面不再跟着每台设备的宽度各自变形，
> 而是**排成同一个样子**，再由界面整体缩放去适配屏幕。

### 一、排版宽度固定下来

★ **之前**：排版用的宽度**跟着设备变** —— 同一份内容在不同尺寸的屏幕上，
换行位置与每行列数都不一样；屏幕越宽，排版越"散"。

★ **现在**：排版一律按一个**固定的逻辑画布（1152 宽）**计算 ——
**任何 16:9 设备上的换行位置与列数完全一致**，与原版的表现对齐。

★ 屏幕适配改由界面**整体缩放**完成：**字号本身不变**，只是整幅画面等比放大或缩小
⇒ 窄屏不再"挤"，宽屏不再"散"。

### 二、背景图按设备尺寸铺满

★ **之前**：背景图会**跟着缩放一起漂移**；而且屏幕比游戏窗口宽时，**右侧会留一条黑边**。

★ **现在**：背景图**按设备尺寸铺满整屏**，且**缩放时一动不动** —— 背景是"底"，不参与缩放。

### 三、缩放控件修掉「越点越小」

★ 点「放大」有时反而变小。原因是加/减缩放的**基准用错了系数**，每次点都被重复乘了一遍。

### 四、许可说明补齐全部源码改动（合规）

★ 本仓库声明「此处列出全部改动」，但实测只覆盖了 **59 / 139** 个改动文件 ——
v0.5.2、v0.5.3 的源码改动，以及更早的控制服务器、界面宿主等一大批文件，**都不在任何补丁里**。

★ 本版补上 `patches/complete-changes.patch`（**139 个文件**，+11142 / −2195，
基线为上游 2026-09-15 的 `5ebd38ad`）—— 应用它即可**完整还原**本仓库构建 APK 时使用的源码。

★ 同时清掉两处会随补丁公开的内部标识（源码注释里的内部工具名与本机截图目录路径）。

### 验证状态

- C# 单元测试：**1157 例 / 通过 1155**（另 2 例为既有的路径安全用例，与本版无关）
- 前端测试：**32 文件 / 622 例全过**；类型检查 0 错
- 背景与排版的最终效果由人工在 Windows 版上实测确认

### 已知限制

- ★ 少数依赖「实时输入框」的功能（如料理名搜索）**暂不支持**
- ★ 立绘**描边**这类依赖「画布叠加」的效果**仍未实现**（它在游戏里默认关闭）

## v0.5.2 · 2026-10-10

> ⚠️ ★★ **本版「排版跟随窗口宽度」的做法已被 v0.5.3 取代** —— v0.5.3 改为
> 「排版宽度**固定**为逻辑画布 1152，屏幕适配交由整体缩放」。
> 读到下面第一节时请连读 v0.5.3，**不要**把"跟随窗口宽度"当成现状。

> ★ 本版属于 **0.5.x 系列（插件与适配）** —— 补齐能力、修正适配，**不是加新玩法**。

### 一、游戏界面排版跟随窗口宽度

★ **之前**：游戏里的按钮行不按窗口宽度排版 —— 按钮会**挤在一起**，或者一整行**超出屏幕**，
右边的内容看不到；界面里的长横线也会画到窗口外面去。

★ **现在**：按钮按**字符列**精确对齐（同一列的按钮上下对齐成一条线），
一行放不下时**按窗口可用宽度自动折行**；窗口拉宽或转屏后，**新内容按新的宽度排版**。

★ 长横线也按窗口宽度绘制，不再超出窗口。

### 二、加载过程中不再误报「游戏已停止」

★ **之前**：大型脚本加载要几十秒，这段时间界面会弹一句**「游戏已停止」** —— 其实游戏好好的，只是还没加载完。

★ **现在**：加载期间不再做这个判断，只有**真正停下来**才提示。

## v0.5.1 · 2026-10-09

> ★ 本版属于 **0.5.x 系列（插件与适配）** —— 补齐能力、修正适配，**不是加新玩法**。

### 一、eraTW 的「神签」配图现在能显示了

★ **之前**：抽到签时，签的**配图出不来** —— 生成那张图的链路是断的。

★ **现在**：配图**正常显示**。

### 二、运行时合成的图，不再被当成「不存在」

★ **之前**：游戏在运行时合成出来的图，会被当成**从来没创建过**。

★ **后果（不报错）**：游戏以为没做成，于是**每次都要重做一遍**同一张图 —— 画面看着正常，其实一直在重复劳动。

★ **现在**：合成出来的图**能被正确识别**。

### 三、带倒计时的输入，超时后不再丢失默认值

★ **之前**：某些带倒计时、且有默认值的输入，**超时后拿到的是空值**，而不是它设定的默认值。

★ **后果（不报错）**：游戏会**走错分支**。

★ **现在**：超时后**正确回落到默认值**。

### 四、说明：本版做的是「补齐与适配」

★ 以上三处**都不是「把坏掉的东西修好」**，而是**补齐原本缺失／接错的能力** —— ★ 与 0.5.x 系列的定位一致。

### 五、已知限制

- ★ 以上三处修复**都还没有做过端到端实机验证** —— 需要玩到**抽签**、**上锁的门**、**BGM 循环**这类场景才会撞上。
- ★ **立绘描边**这类依赖「画布叠加」的效果**仍未实现**（★ 它在游戏里**默认关闭**，默认设置下没有影响）。

## v0.5.0 · 2026-10-09

### 一、eraTW 的「背景图片补丁」现在能用了

★ **之前**：这个补丁开启**看不出任何效果** —— 补丁的状态栏会正常显示「背景图片：启用」，
但画面上的背景**仍然是一片纯黑**。

★ **现在**：背景会显示**实景照片**（按窗口宽度等比缩放铺满），并且**能启用、也能关闭**。

| 操作 | 结果 |
| --- | --- |
| 开启「背景图片」补丁 | ★ 背景出现**实景照片** |
| 关闭该补丁 | ★ 恢复原来的纯黑背景 |

### 二、「时间停止」时，背景会去色

游戏里发动「时间停止」时，会对背景图做一层**颜色处理**。

| | |
| --- | --- |
| ★ **之前** | 背景**没有任何变化**，看起来和平时一模一样 |
| ★ **现在** | 背景会**去色（变成黑白）** —— 与游戏状态对应，一眼能看出「时间停了」 |

★ 这里做的是**去色**（画面失去颜色），**不是把画面调暗**。

### 三、说明：这是补上一块缺失的能力

★ 上面两条**不是**「把坏掉的东西修好」，而是**补上了一块原本就缺失的能力**：

- era 类游戏用一组**图形画布**类的指令来绘制背景这种整屏图片。
  ★ 上游引擎在改造成无头架构时，把这条链路**整体移除**了（源码里保留着说明"已移除"的注释）。
- 本版把这条链路**接了回来**，让这组指令真正产生效果。
- ★ 因此它**不只对 eraTW 有效** —— 其它用到同一组图形画布指令的游戏同样受益。

### 四、已知限制

★ **背景图的颜色处理只做了三种**：**去色**、**亮度**、**透明度**。
游戏若用到更复杂的颜色变换（例如色相旋转、通道互换），**目前不会生效**。

★ **立绘描边一类效果还没做** —— 这类效果依赖「**把一块画布画到另一块画布**」的合成能力，本版没有实现。
★ 不过它在游戏里**默认是关闭的**（选项里标着「(测试)」），不主动打开就完全不受影响。

★ 其余功能不受影响。

## v0.4.5 · 2026-10-09

### 一、可点的字，看得见了

★ **问题**：eraTW 有些界面会把选项文字设成**和背景一样的深色**（黑底黑字），玩家**看不出哪里能点**。

★ **为什么在手机上特别要紧**：

| | |
| --- | --- |
| 电脑上 | 鼠标划过去，那一条会高亮 —— 还能找到 |
| ★ **手机上** | ★ **根本没有「划过去」这个动作** ⇒ 用手机的人**永远看不到**那些选项 |

★ **本版做法**：自动检测 —— **只在「字很暗 且 背景也很暗」时**，给那个按钮补一层**很淡的底衬**。

| 情况 | 行为 |
| --- | --- |
| 黑字 ＋ 黑底（真看不见的） | ★ 补一层淡底衬 |
| 黑字 ＋ 浅底（本来就最清楚） | ★ **一点都不动** |
| 没设颜色的普通按钮 | ★ **一点都不动** |

★ **不加开关** —— 该出现时才出现，正常界面跟以前**完全一样**。

★ **性能**：判断是纯计算，**不去读**浏览器里元素的实际颜色（那会强制重算布局）；且只在换画面时算一次，**不是每帧算**。

### 二、说明：这不是「修 bug」

★ 我们对着**原版**逐项验证过：**原版也是黑字**，靠「鼠标移上去变黄」让人看见 —— 那本来就是给鼠标设计的。
★ 我们给手机的是**常驻**的淡底衬（不依赖悬停）⇒ 这是**给触屏补的替代方案**，不是「把原版弄坏的东西修回来」。

### 三、当时列出的已知问题（★ 已在 v0.5.0 解决）

> ★ **背景图片补丁不生效**（开启后背景仍是黑的）—— 当时的原因是：
> eraTW 的背景图走引擎的**精灵/图形画布绘制**那条路，而这条路径尚未实现。
> ★★ **该问题已在 [v0.5.0](#v050--2026-10-09) 解决** —— 背景图现已正常显示。

## v0.4.2

### 一、前端交互（装上去能直接看到）

| # | 变化 | 为什么 |
| - | ---- | ------ |
| 1 | ★ **输入栏改到屏幕右半边** | 原来输入栏横跨整个屏幕底部，会盖住游戏输出末尾。而这类游戏的**按钮与选项恰好打印在那里** ⇒ 玩家会点不到唯一能推进的输入。改成只占右半边后，选项区（实测全部落在左半边）不再被压住 |

| 3 | ★ **「回到游戏」返回时自动回到底部** | 之前从设置／调试页返回，画面停在**最旧的一行**，每次都得手动划到底 |
| 4 | **文本区底部留出一行余量** | 末行原来紧贴屏幕底边，还会被输入栏压住 |
| 5 | **设置页分成两档** | 「游戏相关」／「高级设置」，默认落在前者 |
| 6 | **设置项说明改成人话** | 原来部分说明是逐字堆术语，现统一为「一句人话 ＋ 括号里放细节」 |

## v0.4.1

> 本版为**纯问题修复版**（无新功能）：修掉一个「**每次更新后第一次读档，画面刷一屏红字**」的老毛病。

### 一、修了什么

**现象**：更新到新版本后**第一次**进入游戏并读档时，画面出现 **22 条警告**，其中 19 条形如

```
警告Lv2:SYSTEM.ERB:38行目:変数"L_Time"はこの関数中では定義されていません
```

**影响**：这不只是"看着吓人" —— 报错的那段是读档时要跑的公共脚本（`@EVENTLOAD`），
它的一部分变量在这条路径上被认为未定义，**可能连带影响读档后的初始化**。

### 二、根因（一句话）

引擎在**惰性物化函数**时，用「**@标签名**」去源文件里认领函数体。它的代码注释里写着前提
「**函数名在单文件内唯一**」—— 而 eraTW 里**不成立**：`SYSTEM.ERB` 有 **3 个 `@EVENTLOAD`**
（`#PRI`/`#LATER` 事件链的设计**本身就是**同文件同名多定义）。

于是物化后一个定义时**取到了第一个同名函数**，把**前一个函数的函数体**解析进了**后一个函数的对象**里 ⇒
**函数体是前者的、私有变量表是后者的（空）** ⇒ 体内用到的变量全部报"本函数中未定义"。

> 这也解释了它为什么"**更新后才出现、之后又自己不见**"：
> 版本号变化会让引擎重建 IR 缓存（速查表），**那一次启动就是"从头读剧本"的冷启动**，缺陷便显形；
> 缓存建好之后的启动走速查表，问题被掩盖。

### 三、改了什么

**一处**（`ErbLoader.cs`，`MaterializeFunction`）：

- **源后背**（从源文件重建函数体）：**改为按行号锁定本函数**，不再按名字取第一个；
- **IR blob 后背**（从缓存重建）：**保持按名字**（blob 内只有一个函数，不可能撞车，且其行号是 blob 内序号）。

> 该约束与该方法既有契约「**源不可读 / 桩行不在 → 返回 null**」一致 —— 按行定位本就是设计意图。
